# Vault, tokens and the restart handoff

Detail moved out of `CLAUDE.md` (section "Architecture") so the file Claude Code loads on every turn stays under its size limit. `CLAUDE.md` keeps the rules; this file keeps the reasoning, the incidents and the measurements behind them. Add new detail HERE and at most one line to `CLAUDE.md`.

Both GitLab project tokens (`COCKPIT_APP_TOKEN`, `COCKPIT_DATA_TOKEN`) are minted from Settings > Keys through `/api/gitlab-tokens/*`, one card per `GITLAB_TOKEN_TARGETS` row. Tokens never live in `.env`: `/api/bitwarden/unlock` maps vault items to `COCKPIT_APP_TOKEN` and `COCKPIT_DATA_TOKEN` (project tokens, COCKPIT- namespaced) plus `JIRA_TOKEN`, `JIRA_TECH_TOKEN`, `CONFLUENCE_TOKEN`, the integration credentials (`FIGMA_TOKEN`, `PROTO_DEPLOY_TOKEN`, `GEMINI_PERSONAL_TOKEN`) and the Amplitude project keys of the usage-analytics module (personal or analytics credentials, not scoped to a git repository; the personal Jira token is matched by the `-jira` item-name suffix and falls back to the technical account). A vault-loaded token lives in the process HEAP and never in the process ENVIRONMENT, and that distinction IS the security property rather than a detail: `ps eww <pid>` prints the environment a process was STARTED with to anyone on the same account, while a variable assigned after boot is invisible there (measured). So `_restartChildEnv` strips every `ENV_SCHEMA` key plus `BW_SESSION` from a respawn, and the open session and its tokens cross to the restart child over an anonymous PIPE instead - one JSON line written to the child's stdin, read only when `COCKPIT_RESTART_CHILD` is set and fd 0 is not a terminal (the first restart after this shipped still comes from a parent that inherits its terminal, and that guard is what stops the child waiting on it). `_parseRestartHandoff` assigns only keys in `BW_DIRECT_ENV_KEYS`, `_bwSession` stays a module variable that never reaches `process.env` - there it would flow into every git, PTY and Playwright child and land back in `ps` one level down - and the payload never touches disk. Values are handed over rather than re-read from the vault because `bw` costs ~1.3 s per `spawnSync` invocation, so a child re-running `bw list` would block its own event loop for seconds while already listening. The price is that a restart no longer revokes: `npm stop`, `bw lock` or a failed adopt is what closes the safe now.

Covered by `tests/test_restart_handoff.mjs` (the real pipe, driven in two subprocesses, because the write side ends in `process.exit`) and `tests/test_server_helpers.mjs`. Which namespace a PROJECT token uses is decided by whose repository it opens. The three repositories Mission Deck itself owns - the app repository, the team data repository and an optional shared module catalog - are COCKPIT- namespaced (`COCKPIT-APP`, `COCKPIT-DATA`, `COCKPIT-MODULES`), which is what keeps a foreign item in the shared collection out of them. An additional data source declared in `DATA_REPO_DEFS` names its own `tokenEnvVar` and `bwItem` there (a `COCKPIT-` item by convention), and `.encryption-key` carries its key under the bare repo id; only the LOCAL directories (`ds-<id>`) are derived, `remoteName` is the source's address.
