# Automation: detail

Detail moved out of `CLAUDE.md` (section "Automation") so the file Claude Code loads on every turn stays under its size limit. `CLAUDE.md` keeps the rules; this file keeps the reasoning, the incidents and the measurements behind them. Add new detail HERE and at most one line to `CLAUDE.md`.

| Command | What it replaces |
|---|---|
| `node scripts/agent-banner.js <skill>/<banner> [--agent a[,b]] [--model m[,n]] [--session-model id]` | Hand-maintained model ids in the spawn banners. Fills `{{MODEL}}` / `{{MODEL_LEFT}}` / `{{MODEL_RIGHT}}` with the model that really runs the agent: `Agent({model})` override > `model:` frontmatter of `.claude/agents/<agent>.md` > session model. Banner-to-agent map: `agents.json` next to the banners. Since 2026-09-13 nobody runs it by hand before a spawn: `scripts/hook-agent-banner.js`, a `PreToolUse` hook on `Agent` in `.claude/settings.json`, reads `subagent_type` and `model` off the call, picks the skill from the transcript's `attributionSkill` (every `.claude/skills/*/banners/agents.json` is a candidate, `_shared` last), renders through this script and shows the result as a `systemMessage` - because the paste the skills asked for was skipped in 83 of 176 spawns (measured over this project's transcripts) and what the terminal showed instead was a narration thinking block ("… plan initialized. · summarized") that Ctrl+O does not expand. The two banners that precede no agent (`prototype/intro`, `review-pr/review` for the built-in `general-purpose`) stay hand-rendered. Covered by `tests/test_agent_banner_hook.mjs`. |
| `node scripts/worktree.js recommend\|create\|prepare\|serve\|stop\|list\|status\|remove\|prune` | A hand-made `git worktree add` followed by copying `.env`, linking `node_modules` and guessing a port - the Phase 6 worktree mode of `/new-idea`. The decisions are pure functions in `scripts/_worktree.js` (`recommendWorktree`, `pickPort`, `rewriteEnvPort`, `removeVerdict`, `PREPARE_TABLE`) and the CLI only gathers facts. `.env` is COPIED with `PORT=` rewritten (3101-3199), never symlinked, because `scripts/_port.js` falls back to 3001 and `npm stop` / `npm run restart` kill by port - a worktree on the default port would kill the main server. Team data (`data-sub-repositories/`) and `.encryption-key` are NEVER linked or copied: two processes on one plaintext directory and one mirror is the 2026-09-05 incident class, and no flag reopens it. `serve` always runs in test mode; `remove` never uses `--force` or `git branch -D`. Detail: [worktrees.md](worktrees.md). Covered by `tests/test_worktree.mjs`, `tests/test_kill_stale_tests.mjs`. |
| `node scripts/demo-export.js --out <prototype-dir> [--dry-run] [--json]` | Copying the `demo/` presentation into a prototype by hand. `--out` must be an EXISTING prototype directory holding `spec.json` (created by `POST /api/prototypes`; otherwise exit 2) - the script never invents an id, never publishes and never runs git. It walks what the page really reaches (`demo/index.html`, the JS import graph from `demo/main.mjs` plus `/js/ds-modal.js` -> `js/utils.js`, CSS `url()`/`@import`, the `index.html` snapshot with every `<script>` dropped), harvests icons and mascot poses by whole-token match, copies `figma-illustrations/`, `assets/agents/` and `demo/assets/proto/` whole, and writes them into a FLAT `assets/` (`_protoCopyAssets` copies files only, so a subdirectory would publish as nothing): `demo__<path>` (`.mjs` -> `.js`), `host__<path>` for host text files, the basename for catalog and binary assets; a duplicate name is exit 1. URLs are rewritten through a CLOSED map (import specifiers in code only - displayed code inside template literals stays as it is - then the absolute prefixes, then `url()`, `src`, `href`); the page's `<html>` gets `data-demo-shell="./host__index.html"`, the one hook in `demo/shell-loader.mjs`. A leftover check over the CODE (comments blanked for the check only; shipped bytes keep them) fails the run on any known absolute prefix; its one allowance is the `pathname.indexOf('/api/')` test in `js/theme-boot.js`, which issues no request. Output is deterministic: sorted lists, no timestamps, unchanged files are not rewritten, `spec.json` `updated` moves only when `demoExport.sourceSha256` moves, and `assets/demo__manifest.json` lists the owned files so a re-run deletes only what it produced before. Covered by `tests/test_demo_export.mjs`. |
