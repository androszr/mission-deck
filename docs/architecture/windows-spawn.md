# Child processes on Windows

Detail moved out of `CLAUDE.md` (section "Architecture") so the file Claude Code loads on every turn stays under its size limit. `CLAUDE.md` keeps the rules; this file keeps the reasoning, the incidents and the measurements behind them. Add new detail HERE and at most one line to `CLAUDE.md`.

The restart child is also the ONE spawn that stays `detached: true` on Windows, and that flag is DETACHED_PROCESS: the new server runs with no console at all, and from then on every console child spawned without `windowsHide: true` opens a visible console window of its own (2026-09-14, from a screenshot: five empty frames cascaded over VS Code - two `git` per installed module from `GET /api/modules/updates`, which the update banner calls on every page load). `scripts/_cp.js` is the answer and is required FIRST in `server.js`: it patches the `child_process` exports in place, so `server.js`, `scripts/_module-git.js` and every `modules/<id>/server/*.js` get the hidden console from a bare `require('child_process')` - the first fix was a wrapper local to `server.js`, which covered exactly the file that did not need it. Two limits are written into that module. Win32 IGNORES `CREATE_NO_WINDOW` (what `windowsHide` sets) next to `DETACHED_PROCESS`, so a literal `detached: true` defeats the patch one level down - the clone stream and the Vite preview now spawn `detached: process.platform !== 'win32'` (the process group only ever existed for the posix kill; Windows kills the tree with `taskkill /T` through `_toolKill`), and `check-conventions` rule `detached-on-win32` warns on any new literal. And `windowsHide` also hides a GUI child's first window, so a spawn that must show one passes `windowsHide: false` explicitly - the caller's options are spread last. Covered by `tests/test_cp.mjs`.
