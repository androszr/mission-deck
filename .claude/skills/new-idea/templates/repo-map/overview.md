## Stack summary

Vanilla-JS SPA (ES modules, no bundler) + one Node.js HTTP server (`server.js`, no framework).
Runtime dependencies: `ws` and `node-pty` only. No database — application state is JSON under the
gitignored `data/`, team data lives in the cloned repo `data-sub-repositories/ds-data/`.
English UI, ASCII-only source. Port 3001 (`.env` `PORT=`, fallback 3001).

The rail's hubs belong to the CORE and are declared in `js/core-hubs.mjs` — eight of them, listed
below. `js/sidebar-flyout-config.js` builds `HUB_FLYOUT` from that file and is never edited by hand.
A module does not create a hub: it declares `sidebar.kind: "page"` plus `sidebar.hub` and its views
are appended to that hub's flyout at boot (`js/module-host.js`). A module that needs a hub of its own
uses `sidebar.kind: "hub"`, and a genuinely new hub is a core change.

Scaffolding shortcut: `node scripts/new-view.js <id> "<Label>" --hub <hub>` writes all four pieces
at once — section, module, `VIEW_REGISTRY` entry and the `pages` entry on that hub's row;
`node scripts/new-endpoint.js <METHOD> <path>` does the server-side equivalent.

## What a plan typically touches

**New view:** `index.html` view-section -> `js/<id>.js` module -> `js/view-registry.js` entry ->
`js/sidebar-flyout-config.js` entry -> cleanup registration if it holds timers -> optional
endpoint + `tests/test_api_*.js`.

**New endpoint:** the right `server.js` section -> `withLock` on any write -> `jsonResponse` on the
way out -> `tests/test_api_*.js` case -> frontend fetch in the owning view module.

**Extend data:** the JSON shape in `data-tier-0` or `data/` -> the server validation/CRUD handler ->
the rendering module -> tests on both sides.

## Footguns

- A view added to `index.html` but not to `VIEW_REGISTRY` and `HUB_FLYOUT` is unreachable.
- A hub id used as a navigation target redirects to the dashboard — navigate to a leaf view id.
- Sidebar collapse state lives in TWO classes (`#sidebar.collapsed` and `body.sidebar-collapsed`)
  plus `localStorage` key `cockpit.sidebarCollapsed`. Toggling one is a bug.
- A write path without `withLock` corrupts JSON under concurrent clients.
- `npm start` from an agent leaves an orphan process — restart through `POST /api/settings/restart`.
- Files under `data-sub-repositories/` belong to another git repo: never stage or commit them.
